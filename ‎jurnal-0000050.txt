1. Anatomi Perangkat Keras: "Zero-Infrastructure Food Scanner"
Modul Amlogic S905X (yang sangat ideal menggunakan unit eks-STB) dirakit ke dalam boks scanner akrilik sederhana yang diletakkan di meja kantin sekolah atau pos pembagian makanan. Mengingat infrastruktur listrik sekolah pedalaman yang rentan, boks ini ditenagai sistem daya hibrida cerdas.
Selain menggunakan panel surya mini, sistem ini terhubung dengan generator rotasi manual yang direkayasa dari dinamo motor pencetak (printer motor) bekas. Jika cuaca mendung dan baterai habis, guru atau petugas cukup memutar tuas mekanis tersebut selama beberapa saat untuk menyuplai tegangan DC konstan ke pin GPIO S905X, memastikan pemindaian nampan makanan tetap berjalan tanpa bergantung pada PLN.
2. Alur Eksekusi Pemrosesan Citra Luring (Edge Vision Pipeline)
Fase A: Ingesti Visual Nampan & Standardisasi Bukti Audit
Saat nampan makanan diletakkan di bawah modul kamera, biner Golang di dalam sistem Armbian akan mengambil citra mentah dari komposisi makanan.
Sebagai alat bukti pencairan dana APBN, citra ini wajib memenuhi standar forensik. Algoritma internal akan langsung melakukan upscaling dan me-render kanvas gambar menjadi resolusi 3000px x 3000px.
Setelah itu, kanvas akan dipotong (crop) secara presisi untuk mengunci rasio aspek vertikal pada 9:16. Standardisasi rasio ini mutlak; ketika data diunggah ke cloud pusat, auditor BGN dapat membuka, menggeser, dan melakukan pembesaran (zoom) mikroskopis untuk melihat tekstur protein pada foto tersebut langsung dari layar smartphone tanpa ada distorsi atau layout shifting.
Fase B: Edge AI Inferencing & Kalkulasi Nutrisi
Model Small Vision Model (SLM) yang dikompilasi menggunakan C++ NCNN memproses gambar luring dalam batasan RAM 1GB. Sistem menghitung Indeks Kepatuhan Nutrisi ($N_{index}$) menggunakan formula:
$$N_{index} = \sum_{j=1}^{k} \left( \omega_j \cdot \iint_{A} C_j(x,y) \,dx\,dy \right) - \Delta_{tolerance}$$
(Di mana $C_j(x,y)$ adalah probabilitas keberadaan kelas nutrisi (protein, karbohidrat, vitamin) pada piksel $x,y$, dan $\omega_j$ adalah bobot wajib dari buku panduan MBG).
3. Transmisi Asinkron & Isolasi Ledger di Joget DX v9
Semua data porsi makanan terenkripsi di dalam eMMC lokal. Ketika mobil vendor katering (yang bertindak sebagai data mule dengan pemancar Wi-Fi lokal) datang mengambil nampan kotor, data log disinkronisasi secara P2P. Mobil ini kemudian mengirimkan payload tersebut ke endpoint API Joget DX v9 Enterprise saat kembali ke kota yang bersinyal.
Protokol Karantina SQL Database:
Untuk mencegah pencairan dana otomatis yang berpotensi korup, kueri SQL penerima tidak boleh langsung memasukkan data ke tabel persetujuan pencairan (ledger utama). Kueri integrasi wajib direvisi untuk menyisipkan data nampan tersebut ke dalam tabel sementara, dengan secara eksplisit menambahkan kolom temporary bernama waiting_for_approval. Data akan terkunci di fase staging ini hingga auditor perwakilan distrik melakukan sampel validasi.
4. Manajemen DOM Front-End & Siklus Hidup Global Scope
Di dasbor Joget DX pusat, auditor dihadapkan pada antrean foto nampan makanan berorientasi 9:16. Untuk mencegah penumpukan data (bottleneck), form antarmuka dilengkapi hitung mundur (countdown timer) batas waktu SLA persetujuan.
Arsitektur logika hitung mundur JavaScript pada form ini tidak boleh dideklarasikan di dalam lingkup lokal, melainkan wajib diletakkan pada lingkup global:
JavaScript
// Deklarasi variabel pada global scope
var iv; 

function startAuditCountdown(duration) {
    if (typeof iv !== 'undefined') clearInterval(iv);
    var timer = duration;
    iv = setInterval(function () {
        // UI render timer
        if (--timer < 0) {
            clearInterval(iv);
            autoApproveMealBatch();
        }
    }, 1000);
}
Implementasi var iv; pada lingkup global ini adalah pengaman sistem. Jika auditor mendeteksi vendor hanya menyajikan setengah porsi telur pada foto 9:16 tersebut dan menekan tombol "Hold & Investigate Vendor", eksekusi tombol eksternal dapat seketika memanggil clearInterval(iv). Ini akan langsung menghentikan sisa hitung mundur, mengunci batch klaim vendor di status waiting_for_approval, dan mencegah sistem melakukan auto-approve yang merugikan keuangan negara.

6. Model Bisnis Monetisasi (Transaction-Based Admin Fee)
Model pendapatannya berbasis B2B Clearing House SaaS. Pemerintah atau vendor katering tidak membayar mahal untuk boks S905X. Anda menanamkan modul smart-billing pada plugin Joget DX. Untuk setiap porsi makanan anak sekolah yang berhasil difoto, dianalisis AI lokalnya, dikirim secara asinkron, dan masuk secara sah ke dalam status waiting_for_approval, sistem akan mendebit biaya layanan (service charge) sebesar Rp25 per nampan. Dengan target 82 juta anak sekolah per hari, modul ini tidak hanya menyelamatkan integritas program MBG, tetapi juga menciptakan aliran kas pasif eksponensial bagi penciptanya.
