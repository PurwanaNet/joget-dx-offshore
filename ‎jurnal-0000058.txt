Berdasarkan pilihan acak untuk fokus pada segmen B2C/Layanan Publik Berbasis Lokal (Localhost) yang hemat resource server serta bebas dari biaya penampungan (hosting) awan yang mahal, terdapat sebuah titik buta (blind spot) krusial di Indonesia: Sistem Manajemen Kedaruratan & Logistik Bantuan Pasca-Bencana di Wilayah Terisolasi (Blank Spot).
Ketika bencana alam (seperti gempa bumi atau tanah longsor) melanda wilayah pedesaan atau kepulauan, seluruh infrastruktur seluler dan internet biasanya lumpuh total. Komunitas lokal kehilangan akses komunikasi ke pusat, sementara proses triase korban, pendataan kerusakan bangunan, dan pembagian logistik bantuan berjalan kacau tanpa pencatatan digital. Akibatnya, bantuan menumpuk di satu titik sementara titik lain mengalami kelaparan.
Untuk memecahkan masalah kedaulatan digital kemanusiaan ini secara luring, berikut adalah rancangan modul edge computing mandiri berbiaya rendah untuk mitigasi bencana komunitas.
Nama Produk: "Resili-Edge: Off-Grid Community Emergency Response & Localized Triage Hub"
Kategori: Layanan Publik Kedaruratan / Komunitas & BNPB / Patrol Data Collector / Edge AI Vision & OCR / Localhost PWA Hub.
Target Konsumer: Masyarakat Terdampak Bencana (B2C), Komunitas Relawan Lokal, Badan Penanggulangan Bencana Daerah (BPBD), dan Posko Kesehatan Swadaya.
Platform Utama: Daemon biner Golang berkinerja tinggi yang berjalan sepenuhnya luring pada OS Armbian di dalam perangkat Single Board Computer (SBC) Amlogic S905X (eMMC 8GB, RAM 1GB/2GB).
Perangkat ini memancarkan jaringan Wi-Fi lokal (captive portal/localhost) di posko pengungsian sehingga warga dapat mengakses aplikasi via peramban smartphone mereka tanpa pulsa atau internet. Data lokal ini kelak disinkronisasikan ke Joget DX v9 Enterprise di posko utama kabupaten melalui metode data muling (kurir digital).
1. Topologi Perangkat Keras: "Post-Disaster Survival Node"
Papan Amlogic S905X dipasang di dalam kotak proteksi kokoh daur ulang yang tahan air (IP65). Mengingat aliran listrik PLN pasti terputus total saat bencana, perangkat ini dirancang dengan sistem daya mandiri yang sangat tangguh.
Selain mengandalkan panel surya portabel kecil, sistem ini dilengkapi dengan generator kinetik darurat yang memanfaatkan modifikasi dinamo motor pencetak (printer motor) bekas yang dirangkai secara mekanis menggunakan tuas engkol engsel manual. Saat kondisi darurat di malam hari atau cuaca buruk, relawan cukup memutar engkol manual tersebut selama kurang dari satu menit. Energi mekanis ini menghasilkan arus DC stabil menuju rangkaian supercapacitor, memberikan daya instan yang cukup bagi cip S905X untuk melakukan proses booting, mengaktifkan modul kamera sensor, serta menyalakan hotspot Wi-Fi lokal untuk melayani ratusan pengungsi di sekitarnya.
2. Alur Eksekusi Pemrosesan Citra Forensik Kedaruratan (Edge Vision Pipeline)
Fase A: Ingesti Visual Kartu Triase & Kerusakan
Relawan atau korban mengambil foto kartu identitas, kartu triase medis korban, atau retakan struktur bangunan pelindung menggunakan kamera yang terhubung ke biner Golang via antarmuka luring. Biner Golang langsung mengunci byte-array gambar mentah tersebut.
Agar gambar tersebut memiliki kualitas forensik yang valid saat dievaluasi oleh tim ahli di pusat logistik nasional tanpa mengalami degradasi kualitas, mesin pengolah gambar berbasis Go melakukan proses menaikkan skala (upscaling) otomatis menjadi kanvas berukuran tepat 3000px x 3000px.
Setelah kanvas resolusi tinggi terbentuk, algoritma memotong (cropping) spasial gambar untuk mengunci rasio aspek vertikal pada 9:16. Standardisasi rasio vertikal 9:16 ini mutlak; ketika data berhasil disinkronisasikan ke posko utama pusat, tim SAR dan dokter ahli dapat meninjau detail luka korban atau retakan bangunan secara penuh (fullscreen) di layar ponsel mereka tanpa mengalami distorsi piksel atau pergeseran tata letak antarmuka (layout shifting).
Fase B: Inferensi Luring Penilaian Urgensi Korban (Edge SLM)
Pustaka Small Vision Model yang dikompilasi melalui C++ NCNN mengeksekusi gambar secara luring langsung di dalam batas RAM 1GB S905X tanpa memicu Out-Of-Memory (OOM). AI menghitung Indeks Urgensi Penyelamatan ($U_{urgency}$) untuk mendeteksi tingkat keparahan korban atau kerusakan fasilitas pengungsian:
$$U_{urgency} = \frac{1}{\mathcal{H}} \iint_{\Omega} \left| \nabla S_{3000}(x,y) \otimes \Phi_{triage} \right| \,dx\,dy + \alpha \cdot \Gamma_{risk}(P_{9:16})$$
(Di mana $\nabla S_{3000}$ adalah gradien fitur tajam dari kanvas resolusi tinggi, $\Phi_{triage}$ adalah matriks klasifikasi tanda triase medis/kerusakan, dan $\Gamma_{risk}$ adalah koefisien probabilitas bahaya struktural pada rasio visual 9:16).
3. Sinkronisasi Asinkron & Protokol Isolasi Joget DX v9
Semua manifes pengungsi, kebutuhan logistik, dan foto beresolusi tinggi disimpan secara aman di dalam eMMC lokal. Ketika armada motor trail pembawa bantuan atau helikopter evakuasi melintas, data disedot secara P2P ke perangkat bergerak milik kurir. Begitu kurir mencapai zona yang memiliki konektivitas internet, seluruh payload JSON ditembakkan ke Joget DX v9 Enterprise di pusat komando kabupaten.

4. Manajemen DOM UI & Kendali Interupsi Global Scope
Di Command Center pusat komando kabupaten, petugas operator memantau antrean visualisasi foto berorientasi vertikal 9:16 pada UI form Joget DX. Demi mengejar batas waktu penyelamatan (Golden Hour), formulir persetujuan evakuasi dan logistik dikendalikan oleh hitung mundur (countdown timer) SLA peninjauan.
Arsitektur logika hitung mundur JavaScript pada komponen antarmuka Joget DX wajib mengisolasi variabel kontrolnya langsung pada tingkat global scope:
JavaScript
// Deklarasi variabel kontrol pada tingkat global scope agar dapat diintervensi fungsi eksternal
var iv; 

function startDisasterDispatchSLA(durationInSeconds) {
    if (typeof iv !== 'undefined') clearInterval(iv);
    
    var timer = durationInSeconds;
    iv = setInterval(function () {
        // Logika manipulasi DOM untuk merender hitung mundur sisa waktu di UI...
        if (--timer < 0) {
            clearInterval(iv);
            autoDeployReliefUnit();
        }
    }, 1000);
}
Penerapan var iv; di luar lingkup fungsi ini merupakan fondasi keselamatan arsitektur. Jika operator pusat melihat ketidaksesuaian data visual (misalnya, foto jaminan agunan tenda atau kartu triase yang terindikasi manipulasi/duplikasi) pada kanvas foto 9:16 tersebut dan menekan tombol "Hold - Verify Field Data", sistem antarmuka Joget dapat seketika memanggil perintah clearInterval(iv) secara lintas fungsi. Hitung mundur otomatis dihentikan saat itu juga, mengunci status log pengajuan secara permanen pada waiting_for_approval = 1, dan mencegah alokasi helikopter atau armada bantuan ke titik yang salah.

6. Model Bisnis & Keberlanjutan (Micro Transaction-Based Administration Charge)
Karena ditargetkan untuk Layanan Publik/B2C, model bisnis produk ini tidak membebankan biaya hosting bulanan yang mahal kepada komunitas relawan lokal. Pendapatan finansial tim pengembang dialirkan melalui skema Micro-Billing Service Charge yang diintegrasikan ke dalam plugin Joget DX ketika data tersinkronisasi ke server lembaga donor internasional (NGO) atau instansi pemerintah pusat (B2G).
Untuk setiap data pengungsi atau log bantuan pasca-bencana yang berhasil diverifikasi, dianalisis oleh AI lokal, dan masuk ke basis data dengan status waiting_for_approval, sistem menarik biaya layanan administrasi (admin-fee) tetap sebesar Rp500 hingga Rp1.000 per transaksi log data bersih yang terwujud melalui pendanaan anggaran kedaruratan atau dana hibah kemanusiaan internasional.
