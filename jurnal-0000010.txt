Menganalisis pergeseran paradigma industri pada hari ini, Selasa 7 April 2026, kita melihat satu masalah raksasa yang belum terpecahkan di sektor B2B kelas berat (khususnya Tambang, Perbankan, dan BUMN). Masalah itu adalah "The Enterprise AI Paradox".
Di satu sisi, seluruh departemen ingin menggunakan AI (OpenAI, Gemini, Claude) untuk mempercepat pekerjaan, menyusun laporan eksplorasi, atau menganalisis kontrak. Di sisi lain, perusahaan sangat ketakutan akan kebocoran data rahasia (seperti titik koordinat tambang, data nasabah, atau neraca keuangan internal) ke server cloud publik milik penyedia LLM. Selain itu, manajemen perusahaan kewalahan mengelola, melacak, dan menagih biaya (kuota token API) yang digunakan oleh ribuan karyawannya secara serabutan.
Untuk tim beranggotakan 1 hingga 5 Senior Software Engineer, ini adalah ladang emas. Berikut adalah rancangan produk level inventor yang mendisrupsi cara korporasi mengonsumsi AI.
Nama Produk: "Nexus-Prompt: Edge AI Token Broker & Privacy Airgap"
Kategori: AI LLM Server (API Token Sales) / Hardware Firewall / AI Agent / FinOps (Financial Operations) Target Pasar: B2B (Perusahaan Tambang, Perbankan, dan BUMN yang memiliki kebijakan Data Privacy tingkat tinggi). Platform Eksekusi: Daemon Service (berbasis Golang) di OS Armbian pada SBC Amlogic S905X (eMMC 8GB, RAM 1GB/2GB), terintegrasi penuh ke Joget DX v9 Enterprise sebagai Mesin Billing & Distribusi.

1. Filosofi & Mekanika Sistem (Pendekatan Arsitek)
Nexus-Prompt bukanlah server yang menjalankan LLM berat secara lokal (karena RAM 1GB/2GB pada S905X tidak akan sanggup). Nexus-Prompt adalah "Satpam Pintar & Kasir" yang berdiri di antara jaringan intranet (lokal) perusahaan dan cloud penyedia LLM (OpenAI/Gemini).
Daripada setiap karyawan atau aplikasi internal memiliki kunci API (API Key) masing-masing yang rawan dicuri, perusahaan hanya membeli satu atau dua Enterprise API Key dari penyedia AI. Kunci master ini ditanam di dalam S905X yang diamankan di ruang server lokal perusahaan.
Cara Kerja Pemrosesan Edge (Di Dalam S905X):
Zero-Knowledge Sanitization (Penyensoran Lokal): Saat karyawan mengetik prompt, misalnya: "Buatkan ringkasan analisa untuk nasabah bernama Bpk. Sudirman dengan saldo Rp50.000.000", prompt ini tidak langsung ke internet. Ia masuk ke S905X. Microservice di S905X mendeteksi entitas sensitif (menggunakan algoritma Named Entity Recognition yang sangat ringan atau Regex terstruktur) dan menyamarkannya (Masking). Prompt berubah menjadi: "Buatkan ringkasan analisa untuk nasabah bernama [PERSON_1] dengan saldo [AMOUNT_1]".
Cloud Execution: Prompt yang sudah aman (tersensor) ini diteruskan ke API OpenAI/Gemini.
De-Sanitization (Pengembalian Data): Saat jawaban dari AI kembali ke S905X, sistem mengembalikan data asli ([PERSON_1] menjadi Bpk. Sudirman) sebelum menampilkannya di layar karyawan. Data rahasia perusahaan tidak pernah menyentuh internet.
Token Metering: S905X menghitung secara presisi berapa input token dan output token yang dihabiskan dalam transaksi tersebut.
2. Orkestrasi "AI Token Marketplace" dengan Joget DX v9
S905X bertugas sebagai mesin pemroses di lapangan, sedangkan Joget DX v9 Enterprise mengambil peran sebagai "Bank Sentral" untuk token AI perusahaan. Di sinilah letak monetisasi dan kontrol bisnisnya:
Internal Token Sales (Penjualan & Alokasi Token API): Joget DX menyediakan portal internal (Dashboard) bagi para Kepala Departemen (Tambang, HRD, Keuangan). Mereka dapat "membeli" atau "mengajukan" alokasi Token API (misal: Departemen Eksplorasi Tambang diberi jatah 10 Juta Token bulan ini). Joget DX mencatatnya dalam Datalist akuntansi internal.
API Policy Gateway: Joget DX melalui API Builder-nya menyinkronkan sisa kuota ini ke perangkat S905X. Jika token sebuah departemen habis, S905X akan menolak request prompt dari karyawan di departemen tersebut hingga manajer mereka melakukan Top-Up kuota via Joget DX.
Audit Trail & Compliance: Joget DX mencatat log penggunaan AI (siapa yang menggunakan, kapan, dan berapa token yang dihabiskan) untuk keperluan audit keamanan siber korporat, tanpa menyimpan isi pesannya (karena isi pesan dijaga kerahasiaannya oleh arsitektur sistem).
3. Mengapa Ini "Sweet Spot" untuk Tim Vibe Coding (1-5 Orang)
Proyek ini memecah monolit menjadi dua microservices yang sangat jelas pembagian kerjanya, sehingga tim kecil bisa bergerak lincah tanpa bentrok:
Tim Edge/Backend (1-2 Orang): Fokus membuat Reverse Proxy di S905X. Dengan vibe coding, Anda bisa meminta LLM merumuskan skrip Golang yang super ringan dan hemat RAM untuk melakukan intercept HTTP request dan manipulasi string (sanitisasi data). Golang dipilih karena sangat efisien di prosesor ARM (Amlogic).
Tim Enterprise/Joget (1-3 Orang): Membangun UI portal marketplace token, dasbor pemantauan, dan workflow approval untuk top-up token. Anda sama sekali tidak perlu membuat antarmuka web dari nol karena semua diselesaikan melalui fitur low-code Joget DX v9.
