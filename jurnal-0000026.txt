1. Filosofi & Anatomi Arsitektur (The Inventor's Perspective)
Kecelakaan kereta, baik karena anjlok (derailment) maupun tabrakan di perlintasan sebidang, selalu didahului oleh anomali vibrasi dan tanda akustik spesifik pada rel baja yang merambat lebih cepat daripada kecepatan kereta itu sendiri.
Sistem cloud tradisional terlalu lambat untuk merespons dalam hitungan milidetik. Kita akan menyulap jajaran Amlogic S905X bekas menjadi Node Sensor Akustik Tepi (Edge). Perangkat lunak di dalamnya tidak menggunakan bahasa yang rentan kebocoran memori. Kita menggunakan Ada (spesifiknya subsistem SPARK)—bahasa pemrograman standar militer dan penerbangan yang secara matematis dapat dibuktikan bebas dari run-time error—untuk mengontrol aktuator palang pintu atau sinyal darurat secara lokal.
2. Alur Eksekusi: "The Deterministic Safety Pipeline"
Fase 1: Ingesti Getaran di S905X (Deep Learning Audio)
Papan S905X dipasang di dalam kotak kedap cuaca di sepanjang rel rawan atau perlintasan. Perangkat ini terhubung via pin GPIO/I2S ke sensor geofon (piezoelectric) yang ditempelkan langsung ke baja rel.
Script C++ ringan melakukan Transformasi Fourier Cepat (FFT) secara terus-menerus terhadap sinyal getaran rel untuk mengekstrak fitur frekuensi.
Model Deep Learning 1D-CNN (Convolutional Neural Network) berukuran di bawah 10MB memproses fitur tersebut. Ia mencari anomali $A$ di mana profil frekuensi melampaui distribusi normal getaran kereta standar:
$$A(x) = \frac{1}{\sigma \sqrt{2\pi}} e^{-\frac{1}{2} \left( \frac{x - \mu}{\sigma} \right)^2}$$
(Jika $A(x)$ 

mendekati probabilitas anomali struktur rel putus atau roda anjlok, sistem memicu interupsi).
Fase 2: Keputusan Otonom via Ada (The Safety-Critical Actuator)
Setelah Deep Learning mendeteksi anomali (misal: "Kereta anjlok 2 km di depan" atau "Ada objek berat di perlintasan"), flag dikirim ke daemon utama yang ditulis dalam bahasa Ada.
Daemon Ada ini bersifat deterministik. Dalam waktu $< 10$ milidetik, ia langsung mengaktifkan aktuator relai fisik untuk menyalakan lampu sinyal merah di jalur tersebut dan membunyikan sirene perlintasan lokal, tanpa perlu persetujuan server pusat atau koneksi internet.
Fase 3: Orkestrasi ERP & HCM di Joget DX v9
Sesaat setelah tindakan pencegahan lokal tereksekusi, Aegis-Rail mengirimkan JSON Payload asinkron melalui VPN ringan ke server pusat PT KAI.
Pembuatan custom Java plugin dan API di dalam ekosistem Joget akan menangani payload ini dengan elegan. API Builder (misal: dengan penamaan spesifik seperti api_rail_anomaly_trigger) akan menerima log tersebut dan memicu desain aksi otomatis.
Integrasi Lintas Modul: Process Tool di Joget DX secara seketika memblokir jadwal kereta di blok jalur tersebut, membuat Helpdesk Ticket level Kritis, dan menggunakan modul HCM untuk melacak lokasi GPS dari teknisi jalan rel terdekat, memberikan mereka perintah kerja paksa langsung ke perangkat seluler mereka.
3. Strategi "Vibe Coding" untuk Tim Kecil (1-5 Engineer)
Ini adalah proyek cyber-physical mumpuni yang dapat dikerjakan secara paralel:
Engineer 1 & 2 (The Signal & Safety Hackers): Menguasai perangkat S905X. Meminta bantuan LLM untuk menulis kode C++ NCNN/TFLite Micro untuk membaca data geofon dan melakukan FFT. Selain itu, mereka menggunakan LLM untuk merancang wrapper bahasa Ada (kompilasi GNAT untuk ARM64) yang memastikan kontrol relai GPIO tidak pernah mengalami crash saat status darurat.
Engineer 3 (The Telemetry Bridge): Fokus membangun jembatan data lokal (MQTT ke HTTPS) agar perangkat keras Armbian ini dapat mengirim paket Heartbeat dan data peringatan dini secara aman ke gateway pusat, meskipun koneksi 4G di area tersebut sangat minim.
Engineer 4 & 5 (The Joget Workflow Engineers): Merancang kanvas Enterprise di Joget DX v9. Membangun dasbor Command Center yang memperlihatkan titik node S905X di atas peta digital (Sistem Informasi Geografis), serta menulis plugin Java kustom untuk otomatisasi transisi status aset jalur kereta dari "Aman" menjadi "Investigasi".
